# 部署网络排查 · 2026-09-30

## 结论与边界

部署失败包含两条不同的数据路径：服务器构建时访问Debian/PyPI官方源，以及GitHub构建后向服务器上传完整镜像包。测量显示两条所测境外路径都慢；腾讯服务器访问腾讯软件源则快。最符合证据的解释是这些跨境连接质量较差，不是服务器整体性能不足。尚不能区分运营商限速、拥塞、丢包等更底层原因，也没有证据证明腾讯异常登录策略造成当前慢速。

尚未修改部署方案、软件源或服务器网络配置；镜像仓库草案未提交。此次只提交独立诊断程序和工作流，临时测试文件已清理。诊断不调用模型、不安装依赖、不启动应用。

## 对此前两次改动的评价

1. 最初构建日志停在Debian约9.7MB索引下载，约四分钟无新输出后SSH Broken pipe/255。此轮已复现官方源下载慢；按采样速度该索引本身需数分钟。SSH连接断开的确切机制未证实，保活可以提高等待期间连接稳定性，但不会加速下载。
2. 改成GitHub打包并SCP上传257MiB，持续约23–27KiB/s；15分钟任务超时。诊断三种传输都慢，说明仅切换SFTP/SCP没有明显改善。打包上传把下载问题换成了慢速传输问题，未处理网络瓶颈。
3. 单纯延长上传超时并不能改善速度；进度显示可用于诊断，不能当作修复。

## 建议的最小修正（待恢复部署时实施）

回到只上传源码、由服务器构建；Docker构建内使用腾讯Debian及PyPI软件源，保留包签名/TLS验证和SSH保活。移除完整镜像SCP上传、预加载镜像包和相关进度流程。暂不引入镜像仓库或额外账号。

先做一次限定时间的实际容器构建验证，再部署并检查健康。不能将此次下载采样当作完整构建或部署成功。

## 测试限制

- 速度包含连接开销，样本最多1MiB；可用于定位数量级差异，不是长期网络带宽保证。
- 国内Python测试只测索引，完整依赖解析与wheel下载尚待实际构建验证。
- 容器内下载测试因Python基础镜像未出现在Docker镜像存储中而跳过；BuildKit缓存不能保证docker run可用。已复现主机下载慢，但容器内腾讯源的DNS与完整构建尚未验证。
- 云安全告警、套餐带宽、运营商路径尚未从腾讯控制台核对；没有修改防火墙、SSH服务或DNS。
