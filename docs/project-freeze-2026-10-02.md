# 项目冻结决策与阶段结论

状态：**正式冻结开发，保留代码、设计与现有成果，等待明确的重新启动决定。**

记录日期：2026-10-02（北京时间）。决策人：项目发起者。范围：AI数字衣橱产品探索及衣橱实验室测试台。

## 1. 为什么冻结

用户最根本的使用点是频繁更换、尝试和比较搭配。理想体验应允许用户换上衣、换鞋、换配饰后快速看效果，而不是每换一套都承担明显费用、等待和失败风险。

当前路线能够完成模型调用，但每个新搭配的完整视觉预览仍需图像生成；要动态展示，还要视频生成。照片不规范时需要先统一个人形象、背景和构图，质量不合格时还会增加重做。人物参考、模板与原素材可以复用，**新的穿搭结果并不能因此免费生成**。

因此，本阶段的冻结判断是：在已探索的技术路线和成本条件下，尚不能同时满足频繁换搭配、低使用成本、稳定保真和顺畅体验。继续增加模板、接口和界面功能，不能消除生成环节的边际成本。项目发起者决定不再继续投入开发和付费试验。

这不是证明所有数字衣橱或所有AI试穿技术都不可行，也不是宣布代码不能运行；是停止推进当前产品路线。免费手动衣柜与低成本文字推荐在原设计中仍有独立价值，但本次没有决定另开一个缩水产品。

## 2. 成本冲突在哪里

|环节|是否可复用|为什么仍影响成本|
|---|---|---|
|个人形象建立|同一用户可长期复用|首次生成、调整、确认仍有成本|
|衣物识别和商品图整理|同一单品可复用|新单品或重做才调用；不应每次重复识别|
|新搭配穿搭图|相同搭配可复用历史结果|更换单品、构图或人物要求通常需要新图像调用|
|动态展示|同一成片播放、下载无需重生成|换穿搭或换动作通常需要新视频调用|
|不合格结果与重试|保存失败可只续下载|视觉不合格的生成可能已经计费，重新生成是新费用|
|存储、带宽、服务器、维护|共享基础设施|不属于模型Token费用，不能漏出总成本|

应核算的是“每套可接受搭配的综合成本”，而不只是单次API标价：

`阶段总费用 = 人物建立 + 图片生成 + 视频生成 + 质量重做 + 其他实际调用 + 基础设施`

`每套合格结果成本 = 对照组全部实际费用 / 人工合格结果数`

已有合格图再次做视频时，新增成本只记视频，但全链路分析仍保留图片前期成本，不能在不同页面重复加总同一笔费用。供应商成功返回文件不等于用户接受该结果。

历史讨论中，用户对部分视频配置的感受约为每条1～1.5元；这只是当时选定规格的成本印象，不是所有模型的当前报价。即使用这个区间做示意，尝试20～30套并分别生成视频，视频部分就约20～45元，尚未包含图片及重做。这里的次数是说明频繁试搭的算术示例，不是用户实测频率。部分高规格或带视频输入的配置更贵，详见历史价目记录。

本仓库没有完成一份覆盖所有模型、真实账单、成功率和用户付费意愿的商业验证报告。冻结决定基于核心体验与已知成本结构之间的冲突，不将不完整测试写成精确的盈利结论。

## 3. 已尝试的降成本与稳定性设计

- 识别只做一次，保存结构化衣物标签；日常推荐优先使用标签，不重复上传全衣柜。
- 默认模特与本人模式分开；个人形象保存后复用，不每次重新建立用户。
- 优先一次原生多图生图，避免逐件换装形成多次调用；参考板保留为普通图片处理的对照选项。
- 先确认穿搭图，视频按需生成；已有结果播放、拖动、循环、下载不调用模型。
- 图片与视频分任务保存，视频失败不重做图片；保存失败只重试下载；提交不确定不自动重复POST。
- 记录真实用量、价格快照和人工账单，以合格结果成本评估，不把估价当真实扣费。

这些措施减少不必要调用与重复扣费，但不足以让“不断换新搭配并展示”成为接近零边际成本的过程。进一步缩短视频、降低质量、减少次数或提高价格，会改变核心体验或使用频率。缓存只解决已生成过的相同结果，不能覆盖大量新组合。

## 5. 重要未完成问题

1. 人物、衣物细节、白底和构图占比由提示词约束，未实现确定性保证。用户曾生成小头像而非完整个人形象；已加强全身提示词并展示实际编译内容，但没有据此证明后续真人生成质量稳定。
2. 首帧会继承原图背景与裁切。缺脚或杂背景不能靠视频提示词可靠修复；先标准化图像有质量收益，也增加成本。
3. 后端仍要求关联AI生成的Look被人工评为`pass`后才能生成视频。这是本站规则，不是供应商API要求。最后讨论了改成明确确认的较宽松流程，**冻结前没有实现该修改**。
4. 多模型账户权限、真实账单、素材角色理解与成功交付率没有完成统一对照验收。官方可接收多张图不代表每张图的语义都被正确遵守。
5. 目前图片适配器主要请求一张输出；批量多图选择、逐图确认及完整批次费用流程仍未完成。
6. “移出素材库”是归档隐藏并保留关联文件、记录与费用，不是释放磁盘。长期多用户删除与保留政策未实现。
7. 79档案的规格、价格和来源保存历史核对日期；恢复前必须重新核验，不把旧刊例当当前报价。

更详细代码边界见[技术架构](architecture.md)。历史排障与变更见[交接时间线](handoff.md)，历史计划中的“待做”不再自动执行。

## 6. 冻结的操作边界

本次保存文档并标明冻结，不删除代码、实验数据、素材、模板或个人形象，不重装服务器，不取消账号或密钥，不将仓库设为GitHub只读归档。也没有创建服务器数据库和素材的离线备份，不能把文档归档理解为运行数据备份。

现有网站、凭据和自动部署工作流保留原状。**冻结开发不等于已停服或停账单**：服务器等基础设施仍可能计费，现有真实生成入口仍可能被用户主动使用。停止服务、备份数据、禁用付费入口或关闭自动部署，应作为单独的明确操作决定。

后续默认只允许阅读、整理和补充事实文档；不继续开发、不扩大模型接入、不运行付费评测、不触发部署或数据迁移。重新启动必须由项目发起者明确提出。

## 7. 重新启动的前提

- 先定义可接受的每套合格穿搭总成本、目标使用频率和等待时间，而不是先增加模型数量。
- 用固定授权样本验证身份、印花、颜色、层次、鞋子、完整身形、背景和手机展示；质量与真实费用同时记录。
- 证明新路线在目标频率下的收入/成本关系成立，包含失败和基础设施。
- 再决定是否继续按需生图视频，或独立研究专用试穿、确定性2D组合、可复用3D等路线。它们目前不是已实现或已证明更便宜的替代方案。
- 恢复前核验依赖、API价格权限、数据完整性和部署版本；另行安排备份及运行维护。
